## Agent Brief

> *This was generated by AI during grilling.* Approved 2026-10-23.

**Category:** enhancement
**Summary:** Add a GUARDED trade access whose building opens on its owner's defeat or on a hand-written guard event

**Current behavior:**
`TradeAccess` is CLOSED, OPEN or ONCE_DEFEATED (`locations/Players.py`). Under
`partner_trade: allies_and_enemies`, `ScenarioPlayerLogic._partner_gate` opens an ONCE_DEFEATED
building on its owner's defeat event (`has_defeated`), whose rule is the scenario's hand-written
`defeat_rules` (`rules/ScenarioRules.set_defeat_event_rules`, events created in `__init__.py` when
`PartnerTrade.needs_defeat_event`). Events are what keep the economy acyclic here: the gate asks an
event item, never the rule behind it.

**Desired behavior:**
- **`TradeAccess.GUARDED`**: a fourth value meaning *once defeated, or guarded*. Set per player and
  building in `Players.py` by ruling only (main opponents included). No record uses it in this
  ticket.
- **Guard rules**: `ScenarioStartingState` gains `trade_guard_rules(scenario_logic) ->
  dict[tuple[Age2PlayerData, Age2BuildingData], Rule]`, hand-written per scenario like
  `defeat_rules`, empty by default.
- **Guard events**: each entry becomes an event location `"<scenario>: Guard <player>'s
  <dock|market>"` (an `Age2PlayerData` method beside `defeat_event`), created only under
  `partner_trade: allies_and_enemies`, its access rule the guard rule.
- **Partner gate**: OPEN opens; ONCE_DEFEATED opens on the defeat event; **GUARDED opens on the
  defeat event or the guard event**; CLOSED never.
- A GUARDED owner counts as tradeable once defeated (`can_trade_once_defeated`), so it gets a defeat
  event and needs `defeat_rules` like any ONCE_DEFEATED owner (`defeats()` raises `KeyError`
  without one).
- **Structural counter**: `ScenarioUnitLogic.can_counter_structurally(target, age)`, the
  structural sibling of `can_counter` (as `can_field_structurally` is of `can_field`): it pays for
  nothing. Guard rules state their own costs with `has_some_source(...)`: routes of *some* only, so
  no bank pays a guard, and a guard can open a base-free cog route.
- **Glossary** (`CONTEXT.md`): **Trade partner** and **Main opponent** gain "or guarded by
  ruling".

**Key interfaces:**
- `TradeAccess`, `Age2PlayerData.can_trade_once_defeated`, a guard-event name method.
- `ScenarioStartingState.trade_guard_rules`, `ScenarioPlayerLogic._partner_gate`, a
  `has_guarded(player, building)` beside `has_defeated`.
- `ScenarioRules`: set the guard event rules beside `set_defeat_event_rules`; `__init__.py`
  creates the guard events beside the defeat events.
- `ScenarioUnitLogic.can_counter_structurally`.

**Acceptance criteria:**
- [ ] A test scenario with one GUARDED dock and a guard rule: the guard event exists only under
      `allies_and_enemies`.
- [ ] The GUARDED dock is a trade partner's on the guard event alone, on the defeat event alone,
      and not with neither.
- [ ] `can_counter_structurally` never asks `can_sustain` (in the shape of
      `TestStructuralFieldingPaysForNothing`).
- [ ] A guard rule paid by `has_some_source` opens Trade Cogs with no base (villagers chopping and
      mining *some*), and the same wood and gold only banked does not.
- [ ] Consistency: every GUARDED record has a guard rule and defeat rules, and every guard rule's
      record is GUARDED. A test goes red on a mismatched record either way.
- [ ] With nothing GUARDED, `TestEveryEasySourceAnswersAsBefore` passes unchanged (no recapture).
- [ ] `AGEIPELAGO_PATH=<Ageipelago> python -m pytest worlds/age2de/test` passes with no existing
      assertion changed.
- [ ] **Fill gate.** Replay the 63 generations in
      `worlds/age2de/fuzz/fuzz_output_lock_items/error/age2de/` before and after: the same
      generations fail. Record both counts here.

**Out of scope:**
- Ruling any building GUARDED: #26 (docks), #27 (markets).
- A land counter or land-threat model for markets: #27, related to #23.
- Any XS (game-side) change.
- Committing: leave the changes uncommitted.

## Comments

> *This was generated by AI during grilling.*

### Grilling (2026-10-23)

- **Every existing enemy dock is a candidate**, read from the maps, not only those recorded
  ONCE_DEFEATED. CLOSED still means "no usable building"; GUARDED is a ruling.
- **Only under `allies_and_enemies`**: the default `allies` stays untouched.
- **The guard counters the owner's navy** (or army, for markets), ruled per building from the
  scenario's starting units and AI scripts; an owner with no navy is ruled per building (no guard,
  the basic guard, or `True_()`).
- **Hand-written per scenario**, like `defeat_rules`. A mechanism splitting guards into leaf and
  route needs was considered and dropped: an **event** breaks the cycle instead, so a guard rule may
  ask anything, the economy included.
- **Costs of *some***, written in the rule as `has_some_source`, over the structural counter. Paid
  counters (`counters()`) would ask easy sources at scale and shut out base-free play.
- **Main opponents** only where a ruling names them.
- **GUARDED is its own access value**, and its owner can also be defeated: GUARDED opens on either
  event.
- **Markets** use the same hook and event; their rulings are #27.
