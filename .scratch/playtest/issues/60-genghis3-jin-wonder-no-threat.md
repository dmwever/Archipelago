# 60: Restore standard victory threats (Wonder, relic) under custom victory

**Reported:** 2026-10-31, playtesting, as "The Jin Wonder in Genghis 3 is no threat, because
custom victory turns it off"

**Status:** done (in-game checks in #78)

**Category:** enhancement

## Report

The Jin Wonder in Genghis 3 does not threaten the player. It is not a win condition.

## What the scenario does with it

The Jin (player 4) are the only ones who build a Wonder here, and no Wonder is placed on the map
at start. Exactly one trigger reacts to it, in **both** the vanilla scenario and the Ageipelago
one:

| trigger | |
| --- | --- |
| `t3 [D1] Jin talk smack` | **IF** player 4 owns 1 of unit **276 Wonder** |
| | **DO** `display_instructions` - a Jin taunt |

That is the whole of it. There is no countdown trigger, no defeat trigger and no AP location
tied to the Wonder, and vanilla has none either. So the AP conversion did not delete a threat
trigger; there was never one to delete.

## Where the threat came from, and where it went

In vanilla the threat is not a trigger at all - it is the **global victory mode**. Comparing
`GlobalVictory` between the stock `4_Genghis_3` (extracted from `cam4.aoe2campaign`) and the
Ageipelago scenario:

| field | vanilla | Ageipelago |
| --- | --- | --- |
| `mode` | **0** | **4** |
| `all_custom_conditions_required` | 0 | **1** |
| `explored_percent_of_map_required` | 0 | **100** |
| `conquest_required` | 0 | 0 |

Under vanilla's mode 0 the standard victory conditions are live, which is what makes a completed
enemy Wonder start a countdown. Ageipelago runs custom victory instead, so the scenario ends only
on its own `declare_victory`, and the standard Wonder condition never applies.

This is **deliberate and project-wide**, not a Genghis 3 slip. All 18 AP scenarios carry
`mode=4, all_custom=1, explored=100`, which matches the commit `aa5dcff "Cleans scenario
resources/victory cons"`. AP needs the scenario to end on `AP Victory`, so standard victory had
to go.

*Not engine-verified:* that mode 0 enables the Wonder countdown and mode 4 suppresses it is read
from the mode difference and the absence of any other mechanism, not from a run.

## The gap

Losing standard victory cost Genghis 3 its only Wonder threat, and nothing replaced it. The
project does model Wonders as objectives elsewhere, so the pattern exists:

| scenario | locations |
| --- | --- |
| Attila 3 | `ATT3_THREATEN_WONDER`, `ATT3_DESTROY_WONDER` |
| Attila 6 | five `Prevent or Destroy <colour>'s Wonder` locations |
| **Genghis 3** | **none** |

Genghis 3's eight locations are Victory, four Defeat-the-X, and three Find-the-X. The Jin Wonder
appears in none of them, and `Genghis3Rules` does not mention it.

## Options

1. **Accept it.** The Jin Wonder becomes flavour, and `[D1] Jin talk smack` is a taunt with
   nothing behind it. Nothing in logic needs changing, because nothing in logic references it.
2. **Restore the threat with custom triggers**, the way Attila 3 and 6 carry theirs: a timer
   started by the Jin owning a Wonder, ending in a defeat unless it is destroyed. That is a
   scenario change, and it would want a matching AP location and rule if the player is expected
   to deal with it.

Worth deciding alongside whether the other 17 scenarios lost anything to the same victory-mode
change - this ticket only checked the Wonder in Genghis 3.

## Agent Brief

**Category:** enhancement

**Summary:** Rebuild the enemy Wonder threat that custom victory switched off, as a shared XS
module that scenarios opt into; turn it on in Genghis 3 and Attila 6, and build the matching
relic threat without turning it on anywhere.

**Current behavior:**
Every AP scenario runs custom victory (`mode 4`, all custom conditions required), so the
engine's standard Wonder and relic countdowns never run. An enemy Wonder that is completed and
left standing has no consequence.

- Genghis 3: the Jin (player 4) may build a Wonder. The only trigger that reacts to it is
  `[D1] Jin talk smack`, which shows a taunt and nothing else.
- Attila 6: triggers place Wonder foundations (Place Foundation followed by an AI goal):
  - Purple (Patavium) #1 at 45 s.
  - Green (Mediolanum) on a timer, which difficulty sets to 1800, 2300 or 2800 s.
  - Red (Aquileia) when P1 brings 2 units into the area around Purple's Wonder site.
  - Orange (Verona) when P1 brings 2 units into the area around Green's Wonder site.
  - Purple #2 when P1 enters the area around Orange's Wonder site, and only once Purple #1
    is dead.

  Each Wonder has a "Prevent or Destroy <colour>'s Wonder" location. No countdown and no
  defeat is attached to any of them.

**Desired behavior:**

*Shared module.* A new XS module (working name `VictoryThreats.xs`) holds all countdown
machinery. A scenario turns a threat on from its own `AP_<Scenario>.xs`, in a single call per
threat:

- Wonder threat: one call per Wonder owner, for example `EnableWonderThreat(owner)`.
- Relic threat: a single call, for example `EnableRelicThreat()`.

New tunables go in `AP_Constants.xs`:

- Base countdown: 200 in-game years.
- Reveal radius: about 10 tiles.

*Wonder threat*, for each enabled owner's Wonder:

1. **Reveal on foundation.** When a Wonder foundation for that owner appears, reveal the map to
   P1 about 10 tiles around the Wonder's centre. In Attila 6 this follows the existing Place
   Foundation triggers. In Genghis 3 the Jin AI builds the Wonder itself, so XS has to notice
   the foundation.
2. **Start on completion.** When the Wonder is completed:
   - announce it to P1;
   - start a countdown, shown as an on-screen timer;
   - add an objective line, e.g. "Destroy the Jin Wonder".
3. **Countdown length** = base + the owner's resource 196 (Wonder Time Modifier, in tenths of a
   year), read when the countdown starts and re-read while it runs. If P1 researches Atheism
   partway through, the remaining time grows.
4. **One countdown per Wonder.** Up to five can run at once in Attila 6.
5. **Cancel on destroy.** Destroying the Wonder cancels its countdown, timer and objective line.
   A new Wonder from the same owner starts the cycle again from step 1.
6. **Cancel on owner defeat.** Defeating the owner cancels every countdown on that owner's
   Wonders, even ones still standing, and stops any new countdown starting for them.
7. **Expiry.** When a countdown reaches zero, P1 loses the scenario.

*Relic threat*: built but enabled in no scenario:

1. **Start.** A single countdown for the whole scenario. It starts when every relic on the map
   is garrisoned in Monasteries belonging to one opponent, or to opponents allied with each
   other. A monk carrying a relic does not count.
2. **Countdown length** = base + the holder's resource 198 (Relic Time Modifier), re-read while
   it runs.
3. **Announce, timer, objective line**, as for Wonders, e.g. "Take a relic from X".
4. **Cancel and re-arm.** It cancels as soon as any relic leaves the holder's Monasteries, and
   re-arms when the holder holds them all again.
5. **Cancel on owner defeat**, as for Wonders.
6. **Expiry.** P1 loses.
7. **Reveal.** When the countdown starts or re-arms, reveal each Monastery holding a relic, using
   the same radius constant.

**Enablement:**

- Genghis 3: Wonder threat for the Jin.
- Attila 6: Wonder threat for Aquileia, Mediolanum, Patavium and Verona.
- No other scenario enables anything. The Wonders in Attila 3 (Constantinople's, placed at

## Comments

### Triage (2026-11-04)

> *This was generated by AI during triage.*

Corrections to the report, checked against the AP `.aoe2scenario` files:

- **Attila 3 and Attila 6 never had threat triggers.** Attila 3's two Wonder locations fire when
  P1 gets near Constantinople's Wonder or destroys it. Attila 6's five fire when the Wonder is
  gone or its owner is defeated. Neither scenario has a countdown or a defeat trigger. Attila 6
  lost its Wonder threat to the custom-victory switch the same way Genghis 3 did, so the gap
  here is not specific to Genghis 3.
- The vanilla `mode 0` comparison could not be re-checked: the campaign files are not on this
  machine. That custom victory suppresses the engine countdown is still not engine-verified.
  The decision above stands either way.
- The 200-year base countdown is the maintainer's choice. No reliable source for the vanilla
  AoE2 DE default turned up.

Decisions from grilling:

- Restore the Wonder threat as a real loss condition in Genghis 3 and Attila 6 only.
- The logic needs no changes for either scenario.
- Build the relic threat generically now, enabled nowhere, so later scenarios can switch it on.

### Implementation (2026-11-05)

> *This was generated by AI during implementation.*

New `VictoryThreats.xs` (Ageipelago), included from `AP.xs`. `InitAP` calls `InitVictoryThreats()`
then a new silent `mutable InitScenarioThreats()`, which Genghis 3 and Attila 6 override.

- The objective line is the timer line: `<colour><player name> Wonder <TIMER>`, or `... Relics
  <TIMER>`. XS cannot add objectives.
- Not engine-verified, check in the playtest:
  - Foundation reveal assumes `xsGetPlayerUnitIds(owner, 276)` returns Wonders under construction.
    If it does not, the reveal happens at completion instead.
  - Completion is build points >= the Wonder's `cTrainTime`.
  - Countdown time is read back from the timer with `xsUnsyncGetTimerTimeRemaining` in years, so
    no years-to-seconds factor is assumed. Expiry is remaining <= 0, checked only once a game
    second has passed since the timer started. Fine in single player.
  - The reveal is a Map Revealer (837) for P1 with its LOS set to `THREAT_REVEAL_RADIUS`. It is
    removed when the Wonder goes.
- Timer ids: Wonders use 0-7 (`THREAT_WONDER_CAPACITY`), relics use 8. Neither scenario uses timers.
- If the holder of all relics changes, even to an ally, the relic countdown is cancelled and re-armed.
