# 05: Attila 1 Forging is in logic without being able to afford a Town Center

**Reported:** 2026-10-19, playtesting

**Status:** done

**Folds in:** [#13](13-easy-resources-no-base-no-villager-line.md)

## Report

In Attila 1, Research Forging is in logic though the player cannot afford a Town Center.
`/explain` (abridged):

```
Research Forging in The Scourge of God (Attila the Hun 1)
    Researches it at the Blacksmith in the Feudal Age -> True
        Can research Forging -> True
            Has Feudal Age -> True
            Has a Town Center to work from -> True
            Any 2 of -> True
                Has a Mining Camp ... Can build a Mining Camp -> False
                Has a Dock ... Can build a Dock -> True
                Has a Mill, standing or buildable -> True
                Has a Lumber Camp, standing or buildable -> False
                Has a Barracks, standing or buildable -> False
            Has a Blacksmith, standing or buildable -> True
        Can easily gather food -> True   (10000 food expected)

The Scourge of God: Has a Town Center to work from -> True
    Any of -> True
        Has Bleda's Camp -> False
        All of -> True
            Has Builder -> True
            Has villagers -> True
```

## Audit (from code)

`ScenarioBuildingLogic.has_tc` (`logic/scenarios/ScenarioBuildingLogic.py:49-56`) is
`standing | can_build_tc()`, and `can_build_tc` is structural only: build permission plus
`has_builders()`. Nothing pays the Town Center's 275 wood / 100 stone.

`ScenarioLogic.has_base` (`logic/ScenarioLogic.py`) does pay for it — where no TC stands, it asks
for the `TOWN_CENTER_WOOD` and `TOWN_CENTER_STONE` items. `has_tc` doesn't share that, and it is
what the age climb uses (`ScenarioAgeLogic._climb_rule`, `& self.scenario.buildings.has_tc()`), so
every age, and every tech behind an age, inherits the unpaid TC.

In this seed Attila 1 has no Bleda's Camp, so villagers come from Attila's Camp / Roman Villagers,
and both Lumber Camp and Mining Camp are unbuildable — no wood or stone income at all.

The same trace shows a wider pattern: the "Any 2 of" age-up buildings (Dock, Mill) and the
Blacksmith are "standing or buildable" without paying their wood either, and only Forging's own
food cost is checked. With no wood income, none of them could actually go up.

## Likely shape of a fix

Make the built path of `has_tc` pay the way `has_base` does (TC wood + stone items, or
`can_pay(TOWN_CENTER.cost)`), and check whether `has_building`'s buildable path should ask for the
building's cost wherever it feeds a research or age-up.

## Agent Brief

> *This was generated by AI during triage.* Approved 2026-10-22 after grilling.

**Category:** bug
**Summary:** Paying for an age or a tech should need a base, through easy food; a base should need the Villager Line

**Current behavior:**
A scenario's age climb asks for "a Town Center to work from" (`ScenarioBuildingLogic.has_tc`), which
is a standing Town Center or one P1 is merely allowed to build. Nothing pays its 275 wood / 100
stone. In Attila 1 without Bleda's Camp, Feudal Age and Research Forging are in logic with neither
Town Center item. Separately, `ScenarioLogic.has_base` never asks for the Villager Line, and easy
food (the raw hunt / herd / forage / fish path of `ScenarioHasEasyResource`) never asks for a base,
so a food-cost tech is in logic off a handful of starting villagers. Attila 2's "Build a Town
Center" rule asks for villagers but not for the Builder profession.

**Desired behavior:**
- A scenario's structural age climb asks `ScenarioLogic.has_building(TOWN_CENTER)` (standing, or
  buildable with Builders) in place of `has_tc()`. It does **not** ask `has_base()` directly: the
  base arrives through the age's price (`can_pay(age.cost)`, food for every age), once raw food asks
  for a base. Everything else the climb asks (the age item, the age-up buildings, the age before) is
  unchanged. `has_reached` used as a prerequisite stays structural. Ages a scenario starts past,
  `age_playable` overrides and fixed-force scenarios behave as today.
- `has_base()` additionally asks for `logic.units.has_villager_item()`, unconditionally, including
  where a Town Center and villagers stand at start. With `shuffle_villager` off this is `True_()`,
  so nothing changes for that option.
- The raw-food half of easy food asks `scenario.has_base()`, matching gold and stone. Endless food is
  unchanged (it already reaches the base through easy wood).
- `ScenarioBuildingLogic.has_tc` and its private half are removed. No other scenario rule needs them.
- Attila 2's local "can raise a Town Center" rule (gating the "Build a Town Center" objective and the
  victory) becomes: `ScenarioBuildingLogic.can_build_tc()` (build permission plus builders) and the
  Starting Town Center Wood and Starting Town Center Stone items. It no longer asks easy income.
- `has_base`'s docstring mentions the Villager Line. `BuildingLogic.can_build_tc`'s docstring
  (ages ask it structurally) stays true and is unchanged.
- Use the glossary's **Base** in names, docstrings and test names.
- Respect ADR-0002: add no direct `has_base()` to any location or prerequisite rule.

**Key interfaces:**
- `ScenarioAgeLogic._climb_rule(into)`: swaps `buildings.has_tc()` for
  `scenario.has_building(Age2BuildingData.TOWN_CENTER)`.
- `ScenarioLogic._has_base()`: gains `logic.units.has_villager_item()`.
- `ScenarioHasEasyResource._food_easily`: the `SufficientRawResources` branch gains
  `& scenario.has_base()`; the `endless_food()` alternative does not.
- `ScenarioBuildingLogic.has_tc` / `_has_tc`: deleted.
- `Attila2Rules.set_rules`: the local `can_build_tc` rule as above, still named
  "can raise a Town Center".
