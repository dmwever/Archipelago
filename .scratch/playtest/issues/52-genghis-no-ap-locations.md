# 52: Genghis Khan scenarios have no AP locations in game

**Reported:** 2026-10-29, playtesting

**Status:** ready-for-human

## Report

Playing the Genghis Khan campaign, the AP locations do not appear in game.

Cause, from the reporter: the AP triggers are missing the trigger **description** and **short
description** fields, and **display as objective** is not set. The locations exist and fire;
they are simply never shown in the objectives panel.

**The locations themselves are wired.** `AddLocations` covers every range
(G1 `30100-30122`, G2 `30200-30202`, G3 `30300-30307`, G4 `30400-30404`, G5 `30500-30507`,

checks should already be sending.

Note the description fields are sparse in the working campaigns too - Joan 1, 3 and 4 and
Attila 1, 2 and 3 set none and still display. So `display_as_objective` is the field that
decides whether a location is visible, and the descriptions are a separate, optional nicety.

## Agent Brief

**Category:** bug, presentation only

**Summary:** 61 AP triggers across the six Genghis scenarios never set `display_as_objective`,
so their locations never reach the objectives panel.

**Why this is human work:** the fields live in the `.aoe2scenario` binaries, and the natural
tool is the DE scenario editor, one trigger at a time. aoe2kit can set `display_as_objective`
through `scen patch` with an `edit_trigger` recipe, but writing the description text means
adding string-table entries as well, so an editor pass is likely cheaper and less risky than a
scripted one.

**Scope:** `display_as_objective` on the 61 AP triggers is the fix. Descriptions and short
descriptions are optional, and the working campaigns mostly do without them.

**Not in scope:** the location wiring, which is already correct and verified above.
