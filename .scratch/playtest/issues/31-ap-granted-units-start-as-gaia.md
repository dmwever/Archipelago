# 31: Units handed to P1 by AP triggers start as Gaia, never capturable

**Reported:** 2026-10-26, raised by the maintainer while grilling [#26](26-dock-guard-rulings.md)

**Status:** needs-triage

**Related:** [#26](26-dock-guard-rulings.md), [#27](27-market-guard-rulings.md), [#28](28-joan4-french-camp-base-unrecorded.md)

## Report

> *This was generated by AI during triage.*

Some objects that an `AP Give ...` trigger hands to P1 start the scenario owned by another player.
Joan 2's dock is the case that surfaced it: it belongs to Burgundy (P2) on the map, so #26 had to
rule it as Burgundy's dock, but `AP Give Dock` makes it P1's.

Most of these are moved to Gaia at runtime by a **staging trigger** (`AP Set Scene`, `AP Set Stage`,
`AP Setup`, `AP Startup`) when the scenario starts, and only later given to P1. So the map, which the
scan and the player records read, still shows them as the original owner's.

The maintainer wants every object that an AP trigger converts to P1 placed under **Gaia** in the map
instead, with its **Capture Flag set to Never**. Gaia objects capture once by default
(`cCaptureFlagOnce`), so without the flag P1 could take them by walking up before the item arrives.

Notes:
- **Source Gaia but object owned by another player** (Joan 2's Town Centers and Dock, Joan 5's
  refugees, Joan 6's La Hire, Joan 3's boats): the staging triggers above move them to Gaia first.
- **Runtime staging already stops capture**: the UGC guide notes that a unit changed to Gaia by
  this effect can no longer be converted. What the staging leaves wrong is the map's owner, which
  is what the scans and `Players.py` records read.
- Each staging effect becomes redundant once its objects are placed as Gaia, and can be removed.
- **Whole-map and whole-player selections** (Attila 1 Bleda, Genghis 2 Tayichi'uds, the Genghis 1
  tribes): moving the source player's objects to Gaia empties that player. Attila 1 records Bleda
  as ignored and Genghis 2 the Tayichi'uds as neutral; Genghis 1 records the tribes as allies.
- **Capture Flag is per object** (`capture_flag`: -1 default, 0 Never, 1 Once, 2 Multiple Times,
  3 Never (Gaia Aggressive)). The vendored parser has it only in format **v1.59**. Attila 2, 4, 5
  and 6 and all of Joan are **v1.58**, so they need re-saving in the editor first.
- Patch notes: some units still convert under Never if they have the Auto-Convert task (sheep,
  monuments).
- Each moved object's trigger effect needs its source player changed to Gaia.
- Non-AP ownership changes to P1 exist too (`Control Attila`, `Capture Orleans`, `Take Burgundy
  Town`, the Tarkan and flag triggers, and others) and are out of the ask as worded.

## How to find what should be Gaia

> *This was generated by AI during triage.* Direction from the maintainer, 2026-10-26.

The best check is to compare each `AP_*` scenario with its **vanilla** original inside the game's
install directory, in the campaign bundles (files such as `cam1.age2campaign`). What the vanilla
map gives the player through triggers, and the AP map moves through staging, is what belongs to
Gaia. Do that comparison when this ticket is worked; the trigger scan above is only a lead.

  first; AoE2ScenarioParser will not write in place)?
