# 57: Joan 2's castles have no "any" branch, so destroying one sends nothing

**Reported:** 2026-10-30, playtesting

**Status:** done

**Related:** [#03](03-location-3616-does-not-exist.md) (the same symptom class)

## Report

Destroying the Northern English castle in Joan 2 did not send a "Destroy One Castle" check.

## Audit (verified by building the world)

> *This was generated by AI during triage.*

### Joan 2 has only the "all" half of a branching pair

`locations/Locations.py` gives Joan 2 four castle locations, every one of them
`OBJECTIVE_BRANCHING_ALL`:

| id | location | type |
| --- | --- | --- |
| 20208 | Destroy Northeast English Castle | `OBJECTIVE_BRANCHING_ALL` |
| 20209 | Destroy Northwest English Castle | `OBJECTIVE_BRANCHING_ALL` |
| 20210 | Destroy Southeast English Castle | `OBJECTIVE_BRANCHING_ALL` |
| 20211 | Destroy Southwest English Castle | `OBJECTIVE_BRANCHING_ALL` |

There is no `OBJECTIVE_BRANCHING_ANY` location anywhere in Joan 2.

Built against a real world, the four appear only under `scenario_branching: all`:

| `scenario_branching` | 20201-20207 (plain) | 20208-20211 (castles) |
| --- | --- | --- |
| `any` **(the default)** | all present | **none present** |
| `all` | all present | all present |

`ScenarioBranching.default` is `option_any`, so the out-of-the-box seed is the one with no
castle locations at all.

### Meanwhile the game still fires them

`AP_Joan_2.xs` registers the whole range and defines all four wrappers:

```xs
AddLocations(20200, 20211);
...
void NortheastCastle() { AP_Check_Location(20208); }
```

So under default branching the player destroys a castle, the scenario trigger calls
`NortheastCastle()`, XS checks 20208, and the apworld has no such location. Same symptom class
as [#03](03-location-3616-does-not-exist.md).

### Genghis 1 shows the shape this should take

Genghis 1 carries both halves, and the "any" half is a separate location with its own
`trigger_call`, its own XS wrapper, and its own scenario trigger:

| id | location | type | trigger_call |
| --- | --- | --- | --- |
| 30101 | Recruit One Tribe | `OBJECTIVE_BRANCHING_ANY` | `RecruitOneTribe` |
| 30102 | Recruit Two Tribes | `OBJECTIVE_BRANCHING_ANY` | `RecruitTwoTribes` |
| 30103 | Recruit Three Tribes | `OBJECTIVE_BRANCHING_ANY` | `RecruitThreeTribes` |
| 30104 | Pick Up Any Relic | `OBJECTIVE_BRANCHING_ANY` | `AnyRelic` |
| 30105-30109 | the five per-tribe ones | `OBJECTIVE_BRANCHING_ALL` | |

`AP_Genghis_1.xs` defines `RecruitOneTribe()`, `RecruitTwoTribes()`, `RecruitThreeTribes()` and
`AnyRelic()`, and the scenario has `AP Recruit One Tribe`, `AP Recruit Two Tribes`,
`AP Recruit Three Tribes` and `AP Any Relic` triggers calling them. `Genghis1Rules` then picks
an arm:

```python
if self.world.pool.scenarios.all_scenario_branches:
    ...the per-tribe locations...
else:
    self.world.set_rule(self.locations[Age2ScenarioLocationData.GEN1_ANY_RELIC], has_monk)
```

Joan 2 has none of that scaffolding - no "any" location, no wrapper, no trigger, and
`Joan2Rules` has no branching arm.

## Agent Brief

**Category:** bug, seed-affecting under the default option

**Summary:** Joan 2's four castle locations are `BRANCHING_ALL` only, so under the default
`scenario_branching: any` no castle location exists and the game's check lands on nothing.

**The fix is the full cross-repo add-a-location walk**, following Genghis 1:

1. `locations/Locations.py`: add a Joan 2 `OBJECTIVE_BRANCHING_ANY` location - the natural
   shape is "Destroy One English Castle", possibly also Two/Three/Four to match the tribe
   counters - with a `trigger_call` name.
2. `AP_Joan_2.xs`: add the wrapper, in ascending id order, and widen `AddLocations` if the new
   id falls outside `20200-20211`.
3. `AP_Joan_2.aoe2scenario`: add the trigger that calls it. This is the part that needs the DE
   editor, and it is why this is `ready-for-human`.
4. `rules/joan_rules/joan_2.py`: add the `all_scenario_branches` arm, so the "any" location gets
   a rule and the four `_ALL` ones keep theirs.

**Joan 2 is the only one.** Swept `Age2ScenarioLocationData` over every scenario with branching
locations:

| scenario | `BRANCHING_ANY` | `BRANCHING_ALL` |
| --- | --- | --- |
| AP_ATTILA_1 | 1 | 5 |
| AP_ATTILA_4 | 1 | 3 |
| AP_GENGHIS_1 | 4 | 8 |
| **AP_JOAN_2** | **0** | **4** |
| AP_JOAN_3 | 2 | 4 |

Every other scenario pairs its halves, so this is a one-off gap rather than a pattern, and
fixing Joan 2 closes it. A test asserting that no scenario has `_ALL` locations without at least
one `_ANY` would keep it closed - that is a pure data assertion, no world build needed.

## Comments

### Fixed (2026-11-03)

Closed by the maintainer. Joan 2 was not reaching victory, and this was the cause: under the
default `scenario_branching: any` none of the four `OBJECTIVE_BRANCHING_ALL` castle locations
existed, so the castle checks the game sent had nothing to land on.
