# 01: Caveman is not applied to scenario rules

**Reported:** 2026-10-15, playtesting

**Status:** ready-for-agent

## Report

In caveman mode, Genghis 1 relic collection should require the Monk Line.

## Audit

No per-scenario rule accounts for caveman. Only the global unit locations do
(`logic/unit_logic.py:43`, `granted & (NOT_CAVEMAN | can_restore(unit))`). Wherever a scenario rule
relies on units an item hands over, the logic counts them even when the game has knocked them down
to Militia.

| Scenario | Rule leans on | Missing in caveman |
|---|---|---|
| Genghis 1 (reported) | Kereyid Tribe item gates the three relics, Recruit Ungirrads, Any Relic, Victory (`rules/genghis_rules/genghis_1.py`) | Monk Line *(mercenary)* |
| Every scenario | `ScenarioResourceLogic._collect_relics`: `has_unit_items(MONK) \| obtains_unit(MONK)` — the second branch skips the items. Affects Attila 3 / Joan 4 starting monks, Genghis 5 Hermit monk | Monk Line on the `obtains_unit` branch |
| Joan 1 | Transport Ships item gates Recruits, both river locations, Victory | Transport Ship line |
| Joan 3 | Transport Ships item gates crossing the sea and the base requirement | Transport Ship line |
| Genghis 3 | Transport Ship item gates Find Engineers, Find Bombards, villagers | Transport Ship line |
| Joan 2 | Trade Carts item gates Bring Carts, Conquer Bridge, can cross; Dock item gives transport | Trade Cart line; Crossbow + Knight lines for the escort; Transport Ship line for the Dock route |
| Joan 6 | French Army item counts toward besieging the town | Archer, Militia, Scout, Knight, Trebuchet lines |
| Attila 2 | Scythian Troops beat Blue alone | Mangudai, Ram, Mangonel lines *(mercenary)* |
| Genghis 3 | Bombards item counts as siege | Bombard Cannon line *(mercenary)* |
| Joan 6 | French Artillery counts toward siege | Hand Cannoneer, Bombard lines *(mercenary)* |

Not affected: villagers (caveman-exempt, `UnitData.is_caveman_exempt`), heroes and escort units, and
every `counters` / `has_military` check (those are training-based and already ask for unit items).

## Open question

Mercenary spawns are caveman-immune in the game: `MercenarySpawn.xs:77` calls
`MarkUnitCavemanImmune`. If that is intended, the *(mercenary)* rows — including the reported
Genghis 1 case — are not real game-side problems, and logic is only being conservative. If the
Kereyid monks did turn into Militia in the playtest, the immunity itself is broken.

Units handed over by scenario triggers (Joan 1/2/3/6, Genghis 3 transport) are not immune, so those
rows are real.

## Agent Brief

> *This was generated by AI during triage.* Approved 2026-10-22 after grilling.

**Category:** bug
**Summary:** Under caveman, scenario rules that count on granted monks must also ask for the Monk's unit items

**Current behavior:**
In Genghis Khan, Crucible (Genghis 1), the Kereyid Tribe item alone gates the three relic locations,
Recruit the Ungirrads, Any Relic, Victory and the scenario's Complete location. With the caveman
option on, the game knocks the Kereyid monks down to Militia, so those relics cannot be collected,
yet logic still considers the locations reachable.

`ScenarioResourceLogic`'s relic collection accepts `has_unit_items(MONK) | obtains_unit(MONK)`. The
`obtains_unit` half is fed by the mercenary grants (Genghis 1 Kereyid and Ungirrad tribes, Genghis 5
Hermit Monks) and has the same blind spot under caveman.

**Desired behavior:**
- With caveman off, logic is unchanged.
- With caveman on, any rule that counts on scenario-granted monks also needs the monk to be restorable,
  using the same `NOT_CAVEMAN | can_restore(unit)` idea that `UnitLogic.can_own_anywhere` already
  applies to granted units. In Genghis 1 that means the Kereyid gate becomes
  "Kereyid Tribe AND (not caveman OR can restore Monk)". It never becomes always false.
- The gate keeps covering Victory and the Complete location: in game, Victory needs four tribes,
  the Ungirrads among them, and they only join for a relic.
- The Ungirrad Tribe is not added to the gate. It stays out of progression (`in_logic` stays false).
- Gate the `obtains_unit(MONK)` branch of relic collection the same way. This covers Genghis 5
  relics through the Hermit Monks, and any scenario that later grants monks.

**Key interfaces:**
- `UnitLogic.can_restore(unit)`: reuse it rather than calling `has_unit_items` directly. It matches
  the XS caveman check (`technologyUnlocked`, `Caveman.xs:134`): the unit's items, plus its upgrade
  tech's item when there is one. The Monk has no upgrade tech, so for the Monk it is exactly
  `has_unit_items(MONK)`, which follows the yaml options:
  - `unitsanity: none`: always true. The Monk has no unit-table row, so caveman leaves it alone.
  - `unitsanity_items: unit_line`: the Monk Line item.
  - `unitsanity_items: upgrades`: the Monk's upgrade tokens.
  - building-item mode: the Monastery's units item.

  "The Monk's unit items" below means whichever of these the seed uses.
- `NOT_CAVEMAN`: the existing `OptionFilter(Caveman, Caveman.option_false)`. Gate on the option with
  `OptionFilter`, not with a Python bool.
- `Genghis1Rules.set_rules`: the `has_monk` rule.
- `ScenarioResourceLogic._collect_relics`.

**Acceptance criteria:**
- [ ] With caveman and unitsanity on, holding the Kereyid Tribe without the Monk's unit items leaves
      every Genghis 1 location the Kereyid gate covers unreachable.
- [ ] With caveman and unitsanity on, holding the Kereyid Tribe and the Monk's unit items makes those
      locations reachable.
- [ ] With caveman off, or with unitsanity off, those locations need only the Kereyid Tribe, the same
      as today.
- [ ] A test covers the cases above with `unitsanity_items: unit_line` (the Monk Line item), run in
      both the all-branches and the single-branch (`GEN1_ANY_RELIC`) setups.
- [ ] With caveman and unitsanity on, relic collection that relies only on mercenary-granted monks
      (for example Genghis 5 with the Hermit Monks but not the Monk's unit items) is unreachable.
      Holding the Monk's unit items makes it reachable again.
- [ ] The existing test suite passes, with `AGEIPELAGO_PATH` set.

**Out of scope:**
- Any game-side (XS) change: no caveman immunity for monks, and no change to mercenary immunity.
- Villager rows: not cavemanified in game.
- Transport Ship, Trade Cart and French Army rows: waiting on
  [issue 16](16-caveman-scenario-ships-and-carts.md).
- Non-monk mercenary rows (Scythians, Bombards, Artillery): immune by design.
- `counters` / `has_military` checks: they are training-based and already ask for unit items.
