# 67: Upgrade techs below a scenario's opening age are free in logic but withheld in game

**Reported:** 2026-11-02, playtesting, as "Demolition Raft does not upgrade to Demolition Ship"

**Status:** done (folds into #64)

**Category:** bug

**Related:** [#72](72-siege-upgrades-do-not-check-their-locations.md),
[#73](73-elite-leitis-restorable-by-an-item-that-does-not-exist.md)

## Report

The Demolition Raft does not upgrade to a Demolition Ship. The Dock research was completed and
the raft still did not upgrade; a raft trained afterwards was still a raft. Checks were going in
around the same time.

## Agent Brief

> *This was generated by AI during triage.*

**Summary:** `researched_at_start` treats every technology below a scenario's opening age as
already researched, but under caveman the game withholds upgrade technologies in exactly that
range. Logic must mirror that exception.

**Current behavior:**

`ScenarioTechLogic.researched_at_start` answers true when a technology's age is below the
scenario's `vanilla_age` and `TechPool.locked_at_start` does not withhold it. With
`existing_techs = vanilla` nothing is withheld, so it answers true for every technology below the
opening age, upgrades included.

`ScenarioUnitLogic.has_upgrade_tech` short-circuits to `True_()` on that answer, so the unit's
upgraded tier needs neither the technology item nor the research. `ScenarioUnitLogic.upgraded_away`
reads the same predicate and concludes the lower tier has been upgraded away.

The game does not behave that way under caveman. `reconstructStartingState` in `Techsanity.xs`
grants technologies below the opening age, with an explicit exception:

```xs
bool grant = true;
if (AP_US_CAVEMAN == 1 && structGetBool(tech, "isUpgrade")) {
    grant = false;
}
```

A withheld technology is not completed and not marked researched, so `initTech` strips it to a
noop and registers its location. Because `is_upgrade` also forces `mustResearch` in
`tryApplyEffect` regardless of the behaviour option, the player needs both the technology item and
the research before the tier exists. The installer makes this reachable: `scenario_needs_age_up`
returns true whenever caveman is set, so every scenario above the Dark Age is rebased to Dark and
the engine's own starting-age pass never researches anything.

**Desired behavior:**

When caveman is enabled, a technology with `is_upgrade` set is not researched at start, whatever
its age relative to the scenario's opening age. Rules that depend on it ask for the technology the
normal way — the research and the item — and the lower tier is not considered upgraded away.

With caveman disabled, behaviour is unchanged.

**Key interfaces:**

- `ScenarioTechLogic.researched_at_start(tech)`: must answer false when caveman is on and
  `tech.is_upgrade`, matching the `grant = false` branch above. Both known callers
  (`has_upgrade_tech`, `upgraded_away`) then follow without changes of their own.
- `Age2TechData.is_upgrade` and the caveman option are the only inputs the exception needs.

**Acceptance criteria:**

- [ ] With caveman on and `existing_techs = vanilla`, `has_upgrade_tech` for a unit whose upgrade
      technology sits below the scenario's opening age resolves to a rule requiring both the
      technology and its item, not `True_()`. Demolition Ship in Attila 6, Joan 5 and Genghis 6
      are the concrete cases; Warships, Pikeman, Crossbowman and the other upgrade technologies
      behave the same way.
- [ ] With caveman off, the same rule still resolves to `True_()`, and no non-upgrade technology
      changes behaviour in either mode.
- [ ] `upgraded_away` does not report a lower tier as upgraded away when caveman withholds the
      technology that would have done it.
- [ ] A red check proves the new rules fail at HEAD.
- [ ] `python -m ruff check --select F,E9` is clean on the changed files, and the logic canaries
      under `worlds/age2de/logic/` and `locations/` pass.

**Out of scope:**

- The XS side. `reconstructStartingState`, `initTech` and `tryApplyEffect` behave as intended and
  the installer's rebase to Dark is what makes them reachable; nothing there needs changing.
- The `existing_techs` modes other than `vanilla`. `locked_at_start` already withholds the
  technology under `find_items`, `only_find_units` and `start_in_dark_age`, so
  `researched_at_start` is already false there.
- Heavy Warships (`Tech(35, -1, …)`), whose effect lives in auto-chained partner technologies.
  That is a separate defect with a separate fix.
