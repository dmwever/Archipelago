# 76: Find Items withholds techs that are not locations in logic, but the game grants them

**Reported:** 2026-11-05, found while triaging [#75](75-caveman-without-techsanity-grants-no-starting-techs.md)

**Status:** done

**Blocked by:** 64

## Report

Under Find Items, logic treats every tech below a scenario's opening age as a **withheld tech**,
including the ones that are not locations. The game withholds only the ones that are locations
and grants the rest at start. Found from code and a logic probe. Not yet seen in game.

### Triage Notes (2026-11-05)

**Status:** ready-for-agent. Blocked by #64, which renames the same predicate.

**Game side, verified from code:**
- `/install` writes each tech below the grant age that is not a location as a grant-only row (`TechData.rows`).
- `reconstructStartingState` (`Techsanity.xs`) withholds a row under `EXISTING_FIND_ITEMS` only when `isLocation` is set. Every other row it completes with `STATE_DONE`.

**Logic side, probed** (Attila + Joan world, Find Items, unitsanity all, at HEAD):

| techsanity | tech | location | scenario | `researched_at_start` | `upgraded_away(MILITIA)` |
| --- | --- | --- | --- | --- | --- |
| units | Loom | no | Attila 2 | False | False |
| generic | Man-at-Arms upgrade | no | Attila 2 | False | False |
| all, unique techs unshuffled | Marauders | no | Attila 6 | False | False |

In all three rows the game grants the tech at start.
- **Stricter than the game (safe):** logic asks P1 to research Loom and Marauders again.
- **Too generous:** under techsanity `generic`, logic still treats Militia as trainable where the game has upgraded it away. With unitsanity `all`, "own a Militia" can then be expected from a scenario that cannot train one.

**Rulings:**
1. **The game is right.** Find Items and Only Find Units withhold only techs that are locations. Start In Dark Age withholds everything. Under techsanity `units`, Loom is granted at start. With unique techs unshuffled, unique techs are granted at start.
2. **Caveman** withholds upgrade techs. After #75, caveman requires techsanity `units` or `all`, and every upgrade tech it can withhold is then a location. So caveman needs no extra condition.
3. **Only Find Units with techsanity `generic`** falls back to vanilla under #75. So in practice this ticket changes only Find Items. The rule is still stated for both modes.
4. **Glossary:** `CONTEXT.md` now defines **Withheld tech**.

## Agent Brief

**Category:** bug
**Summary:** `researched_at_start` must treat a tech that is not a location as researched at start, unless the mode is Start In Dark Age.

**Current behavior:**
`ScenarioTechLogic.researched_at_start(tech)` returns `tech.age < vanilla_age and not withheld_at_start(tech)`. Before #64 the predicate is called `locked_at_start`. `withheld_at_start` returns True for every tech under Find Items, whether or not the tech is in the pool.

As a result, a tech below the opening age that is not a location counts as not researched at start, while the game grants it. Through `upgraded_away`, an upgrade tech that is not a location leaves the lower tier trainable in logic.

**Desired behavior:**
- `researched_at_start(tech)` is True when the tech is below the scenario's opening age and either:
  - it is not withheld; or
  - it is withheld, but it is not one of the seed's locations (`TechPool.includes(tech)` is False) and Existing Techs is not Start In Dark Age.
- `TechPool.withheld_at_start` and `TechPool.reachable` keep their option-only test. `reachable` is what lets a withheld tech become a location. Making it depend on `includes` would be circular, since `includes` calls `reachable`.
- `ScenarioCanResearch` is unchanged.
- Under Vanilla, Only Find Units with techsanity `units`/`all`, Start In Dark Age, and caveman, behavior is unchanged.
- Do not add docstrings or comments.

**Key interfaces:**
- `ScenarioTechLogic.researched_at_start(tech) -> bool`: the only body that changes.
- `TechPool.includes(tech)`, `TechPool.withheld_at_start(tech)` (from #64), and `AgePool.dark_start`: the inputs.
