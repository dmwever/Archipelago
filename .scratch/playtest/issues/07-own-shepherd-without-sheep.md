# 07: Own Shepherd is in logic where no scenario with villagers has sheep

**Reported:** 2026-10-19, playtesting

**Status:** done

## Report

Own Shepherd is in logic even though the only scenario that currently has villagers has no sheep.

## Audit (from code)

The global rule is `UnitLogic.can_do_job_anywhere` (`logic/unit_logic.py`): an Or over scenarios of
`is_unlocked() & scenario.units.can_do_job(job)`, and the profession item.

`ScenarioUnitLogic.can_do_job` (`logic/scenarios/ScenarioUnitLogic.py:130-139`) is
`job_available(job) & job_requirement(job)`:

- `job_available` comes from `ScenarioStartingState.job_available` (`logic/ScenarioLogic.py:35`),
  which defaults to `True_()` for every job. No scenario overrides it.
- `job_requirement` returns `True_()` for every job except Builder, because `job.building` is
  always `None` (`locations/VillagerJobs.py:19`). So the building branch never runs.

So every Own <Job> location except Builder resolves to "some unlocked scenario + the profession
item". It asks neither for villagers (`has_vils`) nor for the resource.

The resource knowledge exists but logic doesn't use it:

- `locations/connections/VillagerJobResources.py` `JOB_TO_SCENARIOS` lists which scenarios have
  sheep, hunt, berries, gold or stone. It is read only by `UnitPool.job_possible`, which decides
  whether the location exists at all.
- `ScenarioResourceLogic._herd` (`logic/scenarios/ScenarioResourceLogic.py:129-134`) already has
  the right shape for herding: `herd_count`, a food dropsite, `has_vils`, and `starting_sheep`.

Same gap for Hunter, Forager, Gold Miner and Stone Miner (resource-limited per `JOB_TO_SCENARIOS`).
Lumberjack, Farmer, Fisherman, Repairer and Herder also never ask for villagers, so they too are in
logic from any unlocked scenario.

## Likely shape of a fix

Make `can_do_job` ask for `has_vils()`, plus a per-job resource condition: either reuse the
economy questions (`can_herd`, `can_hunt`, `can_forage`, ...) or gate on `JOB_TO_SCENARIOS`.

## Agent Brief

> *This was generated by AI during triage.* Approved 2026-10-22 after grilling.

**Category:** bug
**Summary:** An Own <Job> location must need villagers and the worked resource in the same unlocked scenario

**Current behavior:**
`UnitLogic.can_do_job_anywhere` is an Or over scenarios of `is_unlocked() & ScenarioUnitLogic.can_do_job(job)`,
plus the profession item. For every job except Builder, Farmer and Herder, `can_do_job` is
`job_available(job)`, which is `True_()` everywhere, so the rule reduces to "any unlocked scenario
and the profession". The unit region gate asks for a villager, but from any scenario. With Attila 1
unlocked (villagers via Bleda's Camp, no sheep) and the Shepherd profession, Own Shepherd is in
logic.

Separately, `JOB_TO_SCENARIOS` (which decides via `UnitPool.job_possible` whether a job's locations
exist) disagrees with the scenario resource scan.

**Desired behavior:**
An Own <Job> location is in logic when some unlocked scenario satisfies the job's condition, and P1
has the job's profession item:

| Job | Condition in that scenario |
|---|---|
| Shepherd | `has_vils()` and sheep (`herd_count`) in the base or open tier |
| Hunter | `has_vils()` and `hunt_count` in any tier |
| Forager | `has_vils()` and `bush_count` in any tier |
| Gold Miner | `has_vils()` and `gold_count` in any tier |
| Stone Miner | `has_vils()` and `stone_count` in any tier |
| Fisherman | `has_vils()` and `shore_fish_count` in any tier |
| Lumberjack | `has_vils()` |
| Repairer | `has_vils()` and something to repair: a building standing at the start, or `can_build_anything()` |
| Builder, Farmer, Herder, Oyster Gatherer | unchanged |

- Fixed-force scenarios never satisfy a condition.
- The resource checks are static facts from the scan (a scenario with none contributes nothing);
  they are not gathering questions. No drop-off building, no base, no tier gate (`can_defend_resources`,
  `must_steal_base`), and no `starting_*` flag.
- The job condition must not call the economy's gathering questions (`can_herd`, `can_hunt`, ...).
  Those call `has_job`, which calls `can_do_job`, so the rule would recurse.
- `JOB_TO_SCENARIOS` stays a hand-written table, corrected to match the conditions above and with a
  Fisherman entry added. Fixed-force scenarios never appear. Today that means:
  - Shepherd: drop Joan 2; add Genghis 2, 3, 4, 6.
  - Hunter: drop Joan 1; add Genghis 2-6.
  - Forager: add Genghis 2, 3, 4, 6.
  - Gold Miner and Stone Miner: drop Joan 5; add Genghis 2-6.
  - Fisherman (new): every non-fixed-force scenario with shore fish.
- The explain route for a job reports the same condition the rule uses.

**Key interfaces:**
- `ScenarioUnitLogic.can_do_job(job)` / `job_requirement(job)`: carry the per-scenario condition
  above. The economy's `has_job` keeps calling `can_do_job`; the added condition contains no economy
  question, so that stays acyclic.
- `UnitLogic.can_do_job_anywhere(job)`: still an Or over unlocked scenarios plus the profession;
  scenarios whose condition is statically `False_` keep being dropped.
- `JOB_TO_SCENARIOS`: job name to the scenarios with that job's resource, as defined above.
- The resource scan (`ScenarioResources`, per-tier `ScenarioResourceCount`) is the source the
  conditions and the drift test read.

**Acceptance criteria:**
- [x] Regression test: Attila and Joan enabled, Attila starting, `include_professions`. A state with
      only the precollected items, Attila 1's Bleda's Camp and the Shepherd profession cannot reach
      Own Shepherd (Male or Female). Adding Attila 3's unlock makes it reachable.
- [x] A scenario with villagers but only enemy-tier sheep (Joan 2) never puts Own Shepherd in logic.
- [x] A Hunter test: a scenario with villagers and enemy-tier hunt only (Joan 3) does put Own Hunter
      in logic.
- [x] A Repairer test: a scenario with villagers but no standing building and nothing buildable does
      not put Own Repairer in logic.
- [x] Exact-match test: for every job in `JOB_TO_SCENARIOS`, its scenarios equal the non-fixed-force
      scenarios whose scan has the resource (Shepherd: base or open; others: any tier).
- [x] No fixed-force scenario appears in `JOB_TO_SCENARIOS`.
- [x] Existing age2de tests pass (`AGEIPELAGO_PATH` set), and a fuzz run of the committed meta yaml
      shows no new fill failures with `include_professions`.

**Out of scope:**
- The economy's gathering questions (`can_herd`, `can_hunt`, ...) and their tier gates.
- Retiring the `starting_*` flags ([#20](20-retire-starting-resource-flags.md)).
- Paying for the Farm or other buildings on the buildable path (#17).
- Builder, Farmer, Herder and Oyster Gatherer rules.
- Any XS change: the game already checks job ownership by unit type.

### Implementation (2026-10-23)

- `ScenarioUnitLogic.job_requirement` now answers per scenario: Builder and the building jobs
  (Farmer's Farm, Herder's Pasture) as before; otherwise `False_()` where the scan says the
  scenario holds nothing the job works, `has_vils()` where it does, and for the Repairer
  `has_vils()` with `scenario.starts_with_any_building() | buildings.can_build_anything()`.
  It asks no economy question, so `ScenarioResourceLogic.has_job` keeps calling it and the rule
  stays acyclic.
- `ScenarioLogic.starts_with_any_building()` is new: the other `starting_state` accessors live
  there, so the unit module does not reach into the dict itself.
- `VillagerJobResources` gained `JOB_TO_RESOURCE` (the scan count a job works, and the tiers it
  counts in - sheep base-or-open, everything else any tier) and `scenario_has_job_resource`,
  which is `False` for a fixed force whatever the map holds. `JOB_TO_SCENARIOS` is still
  hand-written: Joan 2 dropped from Shepherd, Joan 5 from the miners, Genghis added throughout,
  Fisherman added. Gold Miner, Stone Miner and Fisherman come out as every non-fixed-force
  scenario. (Hunter never listed Joan 1, so there was nothing to drop there.)
- Tests: `TestAJobNeedsItsResourceWhereItsVillagersAre`, `TestARepairerNeedsSomethingToMend` and
  `TestWhichTiersCountForAJob` in `test_unit_rules.py`; `TestTheJobTableMatchesTheScan` in
  `test_scenario_resources.py`. `bases.Age2RuleTestBase.state_with` is new - the precollected
  items plus named ones, no sweep, counting event items so a scenario unlock can be named.
  Two names in `TestVillagerJobs` said the resource jobs were "free"; they are not any more.
- The reported state (Bleda's Camp + the Shepherd profession, Attila 1 the only unlock) now
  fails to reach Own Shepherd; adding Attila 3's unlock puts it back.
- /explain needed no change: the job route already asks `can_do_job`, so Own Shepherd now lists
  only Attila 3-6 and Joan 3-4 as chapters that offer it.
- `has_something_to_mend` is deliberately unnamed: where nothing stands it is one line, and a
  name over one line is over-nesting.
- Knock-on inside the economy: `can_herd` in Joan 2 is now `False_` (its only sheep are English),
  because `has_job` runs through `can_do_job`. That is a tightening in the same direction and no
  test asserted otherwise.
- **Deviation from the brief:** Oyster Gatherer is in `JOB_TO_RESOURCE` with the rest rather than
  left "unchanged", so it resolves to `False_` everywhere instead of `True_()`. Unobservable
  today - no map holds an oyster, so `job_possible` never creates the location - and it keeps one
  table behind both the rule and the pool, so a future oyster map cannot reintroduce this bug.
  Say the word and it goes back to a special case.
- Full suite: 1017 passed under `pytest -n 6`; the 6 reported failures in `test_defeat_rules.py`
  are an xdist artifact (`execnet DumpError: can't serialize <enum 'Age2PlayerData'>`) and the
  file passes 11/11 serially.
- **Fill gate:** `bench/replay.py` over the 100 stored full-shuffle seeds (which set
  `include_professions`): **100/100 ok**, stored as
  `fuzz_output_6f09d7ec6/replay_issue07-job-resource.jsonl`. The stored baselines are all 100/100
  too. `compare.py` against `replay_c6ca31822.jsonl` raises `KeyError: 'order_kept'` - that
  baseline is from 2026-10-09 and `replay_one.py` no longer emits the field. Pre-existing tooling
  drift, not this change.
- Left uncommitted.
