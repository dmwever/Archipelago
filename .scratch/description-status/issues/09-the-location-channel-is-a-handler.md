# 09: The client's location channel is a handler

**What to build:** A `LocationHandler` under `client/handlers/`, built like the others, owning
everything the client sends the game about locations. Today the checked-locations channel is the
only file writer still sitting directly on `Age2GameContext`, while buildings, techs, units,
messages, mercenaries, items, campaigns and storage each have a handler. This moves it, and gives
the scouted classification table from ticket 02 a home in the same class as a second channel.

The two channels keep different cadences and different files:

- **Checked locations**, `locations.xsdat`, written every tick from the checked set.
- **Classification**, scouted once at connect, written once, never per tick.

**Blocked by:** None. Ticket 02 builds its classification writer on this.

**Status:** ready-for-agent

## What moves

Off `Age2GameContext` in `client/GameClient.py`:

- `sync_checked_locations` (the `locations.xsdat` writer)
- `checked_set_armed`, set in `connect`, cleared in `disconnect` and at the end of `ping_game`
- `confirm_checked_set`, the `CheckedLocationsCount` ack comparison
- the `send_checked_set` term that feeds the Free Locations flag in `ping_game`
- the `locations.xsdat` line in `flush_files`

`ClientStatus.checked_locations` is the AP server's set and stays where it is; the handler reads
it rather than owning it.

The house convention is `*Handler` subclassing `FolderHandler`, constructed in `__init__`, rebuilt
in `disconnect`, and handed its folder in `update_game_user_folder`. `UnitHandler` is the smallest
complete example and the model for the test.
